# Geometry Dash 2.0.1.0 - recon area gd-shell (managed Silverlight shell), Sonnet investigator, NOT yet verified by the main session

Feasibility: good

The managed Silverlight shell (PhoneDirect3DXamlAppInterop.dll, 47,256 bytes, IL-only/AnyCPU, targets WindowsPhone v8.0, v2.0.1.0) is tiny. It has 5 types: App, MainPage, EditBox, CallbackImpl and the template-generated LocalizedStrings/AppResources, plus 3 compiler closures. I read all 2,057 IL lines, the 3 embedded XAML files and the component WinMD.

What it does in order:
1. The Silverlight runtime loads AppManifest.xaml and constructs App. App builds a PhoneApplicationFrame, and WMAppManifest's DefaultTask navigates to /MainPage.xaml.
2. MainPage.xaml is one full-screen DrawingSurfaceBackgroundGrid (named DrawingSurfaceBackground, Loaded handler) holding a hidden debug memory overlay.
3. In that Loaded handler the shell creates Direct3DInterop(orientationFlag) and sets one property, WindowBounds. It then calls CreateContentProvider and passes the result to SetBackgroundContentProvider. It passes the Direct3DInterop object itself to SetBackgroundManipulationHandler. It installs three delegates (event, message box, edit box) and registers the managed ICallback through BroswerEventHelper.SetCallback.
4. It forwards only four things to native: orientation (updateOrientation 0/1), the Back key (OnBackKeyPress, always cancelling the OS back navigation), keys from a hidden 1x1 TextBox (Escape/Backspace/Enter/Text via OnCocos2dKeyEvent), and the edit-box result (OnCocos2dEditboxEvent).
5. Pointer input never passes through the shell. The Silverlight runtime hands a DrawingSurfaceManipulationHost to the native object and native registers its own pointer handlers.

Everything else is boilerplate or dead code. Suspend, resume, deactivate, close, size change and OnNavigatedTo are never sent to native; the App lifecycle handlers only store a deactivation time in IsolatedStorage. The 1-second memory-overlay timer (StartTimer) is never called. There are no ads, IAP, WebBrowser, toast, tile or audio calls. The XAML has no WebBrowser, despite the manifest capability.

Managed-only services the game uses, all reached through ICallback or the delegates: EmailComposeTask, MarketplaceReviewTask, MessageBox, Application.Terminate, NetworkInterface.GetIsNetworkAvailable, DeviceUniqueId, ApplicationWorkingSetLimit, the on-screen keyboard and the edit-box overlay.

A native Win32 host can replace the shell with about 12 COM calls plus a small ICallback and 3 delegate objects. The hard part is not in the shell. The Silverlight compositor and DrawingSurfaceManipulationHost roles (driving the native content provider each frame, feeding pointer events) must be emulated. I decoded those only partly (see F06, F09 and F18).

Scratch artifacts are in the session scratchpad under gd (IL dumps, extracted XAML) and re. The repo file tools/arm32/.cache/index_v4.pkl changed during the run; I did not write it, because my runs from the repo failed before saving.
