### F9. Pipeline-state objects: what Unity sends vs the 9_1 rules  [severity: minor (content-dependent), confidence: high]
- Rasterizer (sub_100ac34, CreateRasterizerState vtable+0x58 @0x0100add4): DepthBiasClamp = 0 (OK). DepthClipEnable = Unity raster byte [desc+0x14] (stored @0x0100ada2), but 9_1 requires TRUE (Microsoft "10Level9 ID3D11Device Methods"). Only shaders using "ZClip False" break. Fix: force 1, either by patching `ldrb r3,[r7,#0x14]` @0x0100ada0 -> `movs r3,#1` or in a wrapper.
- Blend (GfxDeviceD3D11::vf11 = sub_100396c): CreateBlendState1 (Device1 +0xb4 @0x01003b1a) is used only for logic ops when caps+0x101 (OutputMergerLogicOp) is true, which never happens at 9_x. The normal path is CreateBlendState (+0x50 @0x01003c5a):

  - IndependentBlend is used only when caps+0xff is set; that flag is off after the F4 patch.
  - Separate alpha factors are copied from the material, but 9_1 has no separate alpha blend.
  Fix in a wrapper: force A2C off and set alpha factors = colour factors.
- Depth-stencil (sub_100a9a4, CreateDepthStencilState +0x54 @0x0100ab3e): separate front/back stencil ops (bytes 4..7 / 8..0xb); 9_1 has no two-sided stencil. UI masks normally use identical faces. Wrapper fix: copy FrontFace to BackFace.
- Sampler (sub_100f858, CreateSamplerState +0x5c @0x0100f9b0):

  - The address table at 0x029b1688 includes MIRROR_ONCE (5), which 9_1 does not allow.
  Fix: clamp aniso to 2 (wrapper, or patch at 0x0100f9a2) and map MIRROR_ONCE -> MIRROR.
- Queries: timer queries are probed with CreateQuery (optional at 9_x), so this is safe.
- Instancing, compute, geometry/hull/domain shaders, UAVs, 32-bit indices and MRT: all gated by caps after the F4/F5 patches, so Unity will not issue them.

### F10. Shaders are the hard part (cross-reference)  [severity: blocker, confidence: medium]
Claim: 9_1 requires vs_4_0_level_9_1 / ps_4_0_level_9_1 bytecode for CreateVertexShader/CreatePixelShader (Microsoft "10Level9 ID3D11Device Methods"). The player creates shaders straight from the stored blobs (vertex shader in sub_100378c @0x01003832, pixel shader in sub_10035ec @0x0100367c) and contains no level_9 or d3d11_9x strings. The game's compiled shaders are therefore expected to be plain SM4.0 DXBC without the 9_x chunk, which the device will reject. Details belong to the sibling area games_recon/bad_piggies_hw-shaders.md (still IN PROGRESS when this area ran).
Proposed fix: re-compile or translate every shader the game uses into 4_0_level_9_1 blobs, either offline from the shader assets or at CreateVertexShader/CreatePixelShader time in a wrapper. Difficulty: hard.

## Summary
Plain language: Unity 2018.4's Direct3D 11 code has no Direct3D 9-class (FL 9_1) mode, but it is not deeply tied to feature level 10 either. The "10.0 required" limit comes from a short list of places, all found:
1. Device creation (F1): the accepted-level list stops at 10.0. One 4-byte patch adds 9_1.
2. Hidden automatic software (WARP) fallback (F2): on your Surfaces, the stock player probably does NOT refuse to start. If WARP exists on that OS (unverified), it quietly renders on the CPU. For GPU rendering, turn that fallback off so failures show up.
3. Capability table (F4) and hard-coded caps (F5): without a patch, Unity would treat a 9_1 GPU as feature level 12_1 hardware. The fix rewrites one 20-byte table row and a handful of constants (32-bit indices, render-target count, NPOT, 3D textures, mirror-once).
4. Formats (F6, F7): the back-buffer depth uses a 32-bit float depth format that 9_1 cannot create, and render textures use typeless formats. Both are small immediate-value patches.
5. Swap chain (F8): fine, apart from one usage flag that is probably illegal at 9_x.
6. Pipeline states (F9): only content-dependent edge cases (anisotropy > 2, ZClip off, alpha-to-coverage, two-sided stencil, mirror-once). A thin wrapper can clean these up.
7. Shaders (F10): the real blocker. Every shader must exist as 4_0_level_9_1 bytecode, which is separate and harder work (sibling hw-shaders area).
Verdict: patch UnityPlayer.dll in place for items 1-6 (about 15 small patches in code and .rdata). Use a thin D3D11 wrapper only as a safety net for the content-dependent state fixes, and for shader replacement if the shaders are translated at load time. A wrapper alone cannot do the job, because the caps table and the format choices live inside Unity and never pass through D3D. GPU rendering at FL 9_1 is possible. The engine patches are easy to moderate. The shader conversion decides whether this is feasible overall.
