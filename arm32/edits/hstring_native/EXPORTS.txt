win32craft_arm32.def - export reconciliation (unit hstring_native)
====================================================================

Facts: pe_imports.md "win32craft.dll exports on ARM", winmain.md section 4, fmod.json (options B/B').
Symbols below were taken from `llvm-nm --defined-only -g` of the ARM objects of win32_host.c + api_compat.c built by
`try_unit.py 00_core hstring_native` (arm32/work/hstring_native/*.arm.obj).

Naming / ABI notes
------------------
* clang thumbv7-pc-windows-msvc emits UNDECORATED symbols: no leading underscore, no `@N` suffix (verified with llvm-nm:
  `Win32Bootstrap`, `RoInitialize`, `Win32CraftXInputGetState` ...). So a .def line is either `Name` (symbol == export name)
  or `Name=Win32CraftSymbol`. Do NOT copy the x86 lines (`Name=_Name@N`), and do not write the `Win32Bootstrap@0` alias.
* All exports are plain AAPCS-VFP (WINAPI/stdcall/cdecl collapse to the one convention; win32_compat.h defines WINAPI empty
  on ARM). Callee-saved r4-r11, args r0-r3 then stack, result r0 (r0:r1 for 64-bit).
* 64-bit REGHANDLE / ULONGLONG parameters are passed in an EVEN register pair: no padding code needed, the declared
  `ULONGLONG` parameter does it:
    EventRegister(const GUID* r0, PENABLECALLBACK r1, PVOID r2, PREGHANDLE r3) -> ULONG r0
    EventUnregister(REGHANDLE r0:r1) -> ULONG
    EventSetInformation(REGHANDLE r0:r1, INT class r2, PVOID data r3, ULONG size [sp]) -> ULONG
    EventWriteTransfer(REGHANDLE r0:r1, desc r2, activity r3, related [sp], count [sp+4], data [sp+8]) -> ULONG
    CoCreateInstanceFromApp(CLSID* r0, IUnknown* r1, DWORD ctx r2, PVOID reserved r3, DWORD count [sp], MULTI_QI* [sp+4]) -> HRESULT  (6 params; review edit 900 fixed the ARM stub, which had 5)
    RoGetApartmentIdentifier(UINT64* r0), RoRegisterForApartmentShutdown(cb r0, UINT64* r1, cookie* r2)
* The loader imports by NAME; the hint in the exe (e.g. XInputGetState hint 6, Win32Bootstrap hint 0) is only a speed hint.
* HSTRING_HEADER on 32-bit = 20 bytes (WindowsCreateStringReference(PCWSTR r0, UINT32 r1, HSTRING_HEADER* r2, HSTRING* r3)).
* Every Windows*/Ro*/error-info export forwards to the genuine combase.dll on ARM (RoGetBufferMarshaler -> wintypes.dll);
  RoGetActivationFactory first asks Win32CraftActivationDispatcher.

Contingency note (Windows RT 8.1, unverified): if the loader reports a missing contract for the API sets in section 2, repoint that
descriptor to win32craft.dll in the patcher; sections 2+3 cover every function the exe imports from those contracts. The
KERNEL32-family contracts listed in pe_imports.md "Contingency" are NOT covered by this ARM export list (the x86 .def forwarders
`Name=KERNEL32.Name` can be re-added line by line if a device reports them missing).
