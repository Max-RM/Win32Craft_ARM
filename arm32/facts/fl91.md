# fl91 - forcing Direct3D feature level 9_1 on the ARM32 host (Minecraft 1.2.8)

Machine-readable: `fl91.json` (32 facts: 23 high / 8 medium / 1 low). Probe script: `arm32/tests/shader_probe.py`
(last output `arm32/tests/shader_probe_last_run.txt`, full results `arm32/tests/shader_probe_results.json`).

## Verdict
* The exe has **no D3D9 renderer** (only `*DX11` classes; imports are `d3d11!D3D11CreateDevice` and `D3DCOMPILER_47!{D3DPreprocess,D3DCompile,D3DReflect}`).
  "D3D9 + FL9_1" therefore means: **D3D11 device at feature level 9_1** (the runtime drives the GPU through the D3D9-class DDI) and `*_4_0_level_9_1` shaders.
* Forcing it is **one hook**: clamp the feature-level array of `D3D11CreateDevice` (IAT `0x00C37A50`) to `{0x9100}`. The game stores the selected level only in
  `GameOwner+0xb8` (passed as `pFeatureLevel`), derives everything from it (VERSION macro, shader target, vertex formats, sampler filters) and never calls `ID3D11Device::GetFeatureLevel`.
* All 197 shader variants (every vanilla/vanilla_base material incl. terrain, water, entity, sky/clouds, particles, ui, text) compile at 9_1 and create fine on a real FL9_1 device.
  Things that cannot work at 9_1 are VR/instanced-stereo only (SV_InstanceID, geometry shaders, texture arrays) and are off in the host.

## 1. Device creation (ARM)
* Only caller: `gfx:GameOwner::InitDevice` 0x5BC258 (BL 0x5BC3A0, WARP retry BL 0x5BC3EC) via thunk 0xA3B968 -> IAT 0x00C37A50.
* Args: `pAdapter=*(owner+0xc4)` (NULL), `DriverType=1` (HARDWARE), `Flags=0`, levels = stack **std::vector** (not a static array)
  `{0xB100,0xB000,0xA100,0xA000,0x9300,0x9200,0x9100}` count 7, `SDKVersion=7`, `ppDevice=&owner[0xc0]`, `pFeatureLevel=&owner[0xb8]`, `ppContext=&renderer[0x110]`.
  If byte `owner+0xbc` != 0 (never set on the host path; default 0 from make_owner) the list shrinks to `{B100..A000}` with Flags=0x20.
* On failure it releases and retries once with `DriverType=5` (WARP); the second result is not checked (null context deref at 0x5BC406).
* `make_owner` (0x13F2A0) pre-sets `owner+0xb8 = 0x9100`. Feature-level readers: `hasFeature` 0x5BC524, `compileShaderProgram` 0x5BDECC, `sub_5BCF90`, `sub_5BC5B8`, `sub_4A3AB4/4A3DF0`, `sub_5B9E90` (name string "DirectX 9.1").
* x86 host (`win32_host.c:9714-9834`): `flags|=0x20`, Win7 11_1 filter, WARP retry, captured base device/context. ARM keeps only `flags|=0x20` + the new clamp.
* Offline check: `D3D11CreateDevice(levels={0x9100})` -> S_OK, selected 0x9100, GetFeatureLevel 0x9100 on hardware and WARP.

Hook (default `cap=0x9100`; `--feature-level=9_1|9_2|9_3|10_0|10_1|11_0|11_1|game`, env `WIN32CRAFT_FEATURE_LEVEL`, default 9_1 on ARM):
```c
flags |= 0x20;                                    /* BGRA */
if (cap) { n = 0;
  if (levels && count) for (i = 0; i < count && n < 8; ++i) if (levels[i] <= cap) out[n++] = levels[i];
  if (!n) out[n++] = cap;  levels = out; count = n; }
return real_D3D11CreateDevice(adapter, driver_type, software, flags, levels, count, sdk, dev, selected, ctx);
```

## 2. Shader profile selection
| FL (owner+0xb8) | suffix (`0x5BDD0C`) | major_minor | target | VERSION |
|---|---|---|---|---|
| 0x9100, 0x9200 | `_level_9_1` | 4_0 | `vs_4_0_level_9_1` / `ps_4_0_level_9_1` | 37120 / 37376 |
| 0x9300 | `_level_9_3` | 4_0 | `*_4_0_level_9_3` | 37632 |
| 0xA000 | "" | 4_0 | `*_4_0` | 40960 |
| 0xA100 | "" | 4_1 | `*_4_1` | 41216 |
| 0xB000/0xB100 | "" | 5_0 | `*_5_0` | 45056 / 45312 |

* Stage prefix (`0x5BDDA0`): 0 `vs`, 1 `ps`, 2 `gs`; no compute. Target = prefix + `_` + major + `_` + minor + suffix.
* `D3DCompile` (single site 0x5BE4BA): src=`this+0x58`, size=`this+0x68`, macros = **only** `VERSION=<decimal FL>`, include = game `HeaderInclude` (vtable 0x0136B164), entry `"main"`, **flags1=0x8000** (OPT level 3), flags2=0.
  Other defines (`R8G8B8A8_SNORM_UNSUPPORTED` at FL<10, `MSAA_FRAMEBUFFER_ENABLED`, `VR_MODE`, `INSTANCEDSTEREO`, `TEXEL_AA_FEATURE`, material `defines`) are prepended as `#define X` text.
* Sources: `shaders/hlsl/<name>.hlsl` (+ `ShaderConstants.fxh`, `util.fxh`) via the game's file layer; **no per-FL variants**. Nine GUID dirs under `data/shaders` hold pack-specific replacement fragment shaders (all compile at 9_1). `glsl/` and `gnm/` are unused.
* Geometry shaders exist only as `vrGeometryShader` and are loaded only in VR; non-VR programs have an empty GS source -> never compiled. `gs_4_0_level_9_1` does not exist.
* Compiled blobs are cached in `ShaderCache2` keyed by hash(preprocessed source) only -> **wipe the cache when the FL changes** (plain 4_0 blobs are rejected by a 9_x device with E_INVALIDARG).

## 3. Feature-level gated behaviour (ARM code, confirmed against D3D11 CheckFormatSupport probes)
| area | 9_1 / 9_2 | 9_3 | >= 10_0 |
|---|---|---|---|
| `hasFeature` ids 0,5,6 (FL>=10) | false | false | true |
| `hasFeature` id 8 (FL>=9_3) | false | true | true |
| position vertex format (`0x5BCF90`) | R32G32B32_FLOAT (6), stride 0x10 | R16G16B16A16_FLOAT (10), stride 8 | same as 9_3 |
| attr types 3-5 | R16G16_SNORM (37) | R16G16_SNORM | R16G16_UNORM (35) |
| attr type 2 | R8G8B8A8_UNORM (28) + define `R8G8B8A8_SNORM_UNSUPPORTED` | same | R8G8B8A8_SNORM (31) |
| sampler TexelAA (`0x5BC5B8`) | demoted to filter 2 | demoted | allowed only if displaySettings+0x31 |
| HLSL TEXEL_AA / LOD path | off (`VERSION<0xa000`) | off | on if enabled |
| TEXTURE_0 as Texture2DArray | no | no | only with stereo/ARRAY_TEXTURE_0 |
| colour quantisation (`0x4A3DF0/4A3AB4`) | FL<10 variant | FL<10 variant | normal |
| instanced draws / GS / SV_InstanceID | never issued (VR only), not compilable | same | VR only |
Probe (`CheckFormatSupport`, desktop driver): R16G16B16A16_FLOAT has no VB support at 9_1/9_2, R16G16_UNORM none below 10, R8G8B8A8_SNORM no VB below 10, D32_FLOAT not below 10 -> the game's own fallbacks match the runtime exactly.
Things that would break at 9_1 if enabled: VR/stereo (depth ArraySize 2 -> E_INVALIDARG, tested), D32_FLOAT depth, texture arrays, R32 index buffers beyond FL9_2 limits, textures/backbuffer > 2048 on real 9_1 hardware, MSAA (Tegra 9_1 has none).

## 5. Host-side FL9_1 compatibility (`initialize_game_d3d`, present, scissor, draw trace)
* Swap chain (`IDXGIFactory::CreateSwapChain`, B8G8R8A8, 2 buffers, DISCARD) + D24S8 depth + backbuffer RTV + `Present(1,0)` + QI IDXGIDevice3 / ID3D11DeviceContext1/2 / annotation / IDXGIAdapter3: all S_OK on FL9_1 (hardware and WARP).
* Invalid/limited at 9_1: stereo (display+0x19) must be 0; no D32_FLOAT; no MSAA; texture/backbuffer size <= 2048 on real 9_1/9_2 (4096 at 9_3); no DrawInstanced/instance count > 1 (game only does that for VR).
* Keep: scissor fix (context vtable slot 45), Present hook (slot 8). Drop: `install_draw_trace`, all Win7 branches.

## 6. Risks that can still fail on real FL9_1 hardware
1. Texture/backbuffer > 2048 px (9_1/9_2), NPOT textures with mips + wrap (808 vanilla PNGs have an NPOT side; creation succeeds, sampling is only conditionally supported).
2. 32-bit index buffers (R32_UINT) need FL>=9_2 with max index 2^20-1; 9_1 is 16-bit indices only (game picks index size per mesh).
3. Stale `ShaderCache2` from another FL; first-run compile time of up to ~197 variants on a slow ARM CPU.
4. Driver-level shader limits of the level_9 blobs (all variants are tiny: max 49 VS / 43 PS SM4 instructions, 6 interpolators) - low risk, but real Tegra drivers may differ.
5. D3D11.2 interfaces (ID3D11DeviceContext2, IDXGIDevice3) are queried unguarded: need Windows RT 8.1 / Win10 ARM32 (not RT 8.0).
6. InitDevice does not check the WARP-retry result (null deref) - host must verify device/context after `init_device`.
7. MSAA/TexelAA/VR options must stay off; any resource-pack shader using SV_InstanceID or geometry shaders will fail to compile at 9_1.
